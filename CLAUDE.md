# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A Godot 4.7 (Forward Plus, GDScript) 2D game, a school DDU project ("Undulaternes DDU projekt 2"). It plays like "Papers, Please" but for taxes: customers hand over tax forms (`TaxForm`, e.g. A-indkomst, aktieindkomst, ejendomsværdiskat), the player works out how much tax is owed, writes the amount in the form's answer field and drags the form back to the customer. The closer the answer, the higher the pay. The tax forms are modelled on the Danish tax system. The README, code comments and most in-game text are in Danish (some game-loop text, like the quota and game-over messages, is still English). Players can log in against a Supabase database.

## Running

There is no build step, linter or test suite. Open the project in the Godot 4.7 editor, or use the CLI (if `godot` is on PATH):

- Run the game (main scene = title screen): `godot --path .`
- Run one scene: `godot --path . "res://!DEBUG/DebugScenes/test_boards/test_boards.tscn"` (quote paths, since folders contain `!` and `&`)
- Headless check: `godot --headless --path . --quit`. `godot --headless --path . --import` rescans the project, registers `class_name`s and creates the `.uid` files for new scripts (commit those with the script).

## Team conventions (from README)

- **All testing must happen in `!DEBUG/`.** Each test is a small scene under `!DEBUG/DebugScenes/<name>/` whose script builds objects in code (e.g. `test_boards`, `test_desk`, `test_rulebook`). `!DEBUG/TestTools/TestBot.gd` (`TestBot`) drives automated tests: fake mouse/keyboard (`click`, `drag`, `type_text`, `press_key`, `press_action`), `screenshot()` (saved to the git-ignored `!DEBUG/Screenshots/`, skipped in `--headless`), and `check()` / `check_equal()` / `check_near()` + `finish()` (exit code 1 if anything failed).
- Folder layout matters. Put new code where it belongs:
  - `Classes/`: scripts for objects created many times, grouped into `CustomerClasses/` (`Customer`, `CustomerData`), `ObjectClasses/` (`Board`, `TaxForm` and its forms, `RulebookPage`, `Letter`, `NotePaper`), `UIClasses/` (`Dialogue`) and `DatatypeClasses/` (`Weighted_Array`).
  - `Scenes&Scripts/`: Godot scenes plus scripts for one-off things: `main/`, `work_place/`, `GameObjects/` (bell, desk), `InteractiveScenes/` (title screen, login, rulebook), `UIScenes/` (dialogue) and `!ScriptDependencies/` (the `Global` and `Tweens` autoload scripts).
  - `Setup/`: code that runs as soon as the game starts, i.e. autoloads such as audio.
  - `Resources/`: audio, sprites, images, UI assets, customer data (`Customers/`), letters (`Letters/`) and rulebook pages (`Rulebook/Pages/`).
  - `Addons/`: third-party plugins: `supabase` (the database client, enabled in `project.godot`) and `Calculator`.
- Naming: scenes and scripts use `snake_case`. Class names are PascalCase (`class_name Customer`, `CustomerData`) and their files share the class name (a few use underscores: `A_Indkomst`, `Weighted_Array`). Resource files can be named freely.

## Architecture

- **Scene flow**: `titlescreen.tscn` (`Scenes&Scripts/InteractiveScenes/`, the main scene) → PLAY → `main.tscn` (`Scenes&Scripts/main/`, which instances `work_place.tscn`). The title screen's "Log ind" button opens `login.tscn`, which returns to the title screen.
- **Autoloads** (`project.godot`), called globally by name:
  - `AudioPlayer` (`Setup/AudioSetup/audio_stream_player.tscn`): a node with a `MusicPlayer` child (sound effects get a temporary `AudioStreamPlayer` each). Use `AudioPlayer.play_custom_track(path)` (looping music, no-op if already playing), `stop_music()` and `play_sound_effect(path)`. Volume: `default_bus_layout.tres` defines a `Music` bus (used by `MusicPlayer`) and an `SFX` bus (used by every player that `play_sound_effect` creates), both sending to `Master`. Any new non-music `AudioStreamPlayer` must also set `bus = &"SFX"`, or the sound-effects slider won't affect it. The user's volumes (0..1) live on the buses via `set_music_volume(v)` / `music_volume` and `set_sfx_volume(v)` / `sfx_volume` (0 mutes the bus). `save_settings()` writes both to `user://settings.cfg`, which `_ready()` loads. Fades and resets (the game-over fade in `work_place.gd`, the reset in `main.gd`) use `music_player.volume_db` instead, so they don't clobber the user's setting. The sliders are `%MusicSlider` and `%SfxSlider` on the title screen.
  - `DialogueBox` (`Scenes&Scripts/UIScenes/Dialogue/dialogue_box/`): bottom dialogue panel with a speaker name.
  - `DialogueText` (`Scenes&Scripts/UIScenes/Dialogue/dialogue_text.tscn`): a floating text line, used for customer greetings.
  - `Supabase` (`Addons/supabase/Supabase/supabase.gd`): the database client. It reads the URL and anon key from the project settings `supabase/config/*`, falling back to `Addons/supabase/.env` (git-ignored; copy `example.env`).
  - `Global` (`Scenes&Scripts/!ScriptDependencies/Global.gd`): `PIXEL_SCALE`, `game_over` (while true, boards ignore input), `savings` (the money kept after each finished sprint's quota, saved to the database for logged-in players) and the login state: `current_user` (`{"id", "user_name"}`, empty = not logged in, never holds the password) and `is_logged_in()`. Log out with `Global.current_user = {}`. The login only lasts for the session: nothing is saved to disk. `id` arrives from JSON as a float, so use `int(...)` before putting it in a query (`str(1.0)` is `"1.0"`, which a bigint filter rejects).
  - `Tweens` (`Scenes&Scripts/!ScriptDependencies/Tweens.gd`): `wobble(node)` (rotate + scale bounce, awaitable) and `bob(node)`.
- **Database** (Supabase): the `Users` table has `id`, `created_at`, `user_name` (unique: constraint `Users_user_name_key`, so a duplicate insert fails with `task.error.code == "23505"`) and `user_login` (the password, in plain text). Insert with `SupabaseQuery.new().from("Users").insert([{...}])`: the row goes in the JSON body, so its values are not `uri_encode()`d. Registrations are limited to **30 per IP per hour** by the PostgREST pre-request function `private.check_request()` (set via `alter role authenticator set pgrst.db_pre_request`). It only acts on `POST /Users`, reads the IP from `cf-connecting-ip` (the first `x-forwarded-for` entry can be forged by the client), logs each new user in `private.registration_log` (failed inserts roll back their log row) and rejects with HTTP 429, `task.error.code == "rate_limit"`. Each run of `test_register` uses 1 of the 30. Query with `var task = await Supabase.database.query(SupabaseQuery.new().from("Users").select(PackedStringArray([...])).eq(column, value)).completed`. Treat it as failed if `task.error != null or not task.data is Array`: a network failure gives `data == null` with no error. `SupabaseQuery` puts filter values into the URL unencoded, so `uri_encode()` any user-typed value that may contain `&`, `#`, `+`, `%` or spaces. The `Progress` table holds the saved progress, one row per user: `user_id` (primary key and foreign key to `Users.id`, `on delete cascade`, so deleting a user deletes their progress), `sprints_completed` and `savings` (`numeric(12,2)`). It is written with an upsert, `SupabaseQuery.new().from("Progress").insert([{...}], true)`, which creates the row the first time and overwrites it after that. A user with no row is a new player. Row Level Security is **off** on `Users` and `Progress`, so anyone with the anon key (which ships with the game) can read every row and edit anyone's progress. `Scenes&Scripts/DBConnect.gd` (run by `!DEBUG/DebugScenes/test_db/`) prints the whole table.
- **Login** (`Scenes&Scripts/InteractiveScenes/login.tscn` + `login.gd`): username and password fields, "Log ind" and "Registrer bruger" buttons, a status label and a "Tilbage" button. The username field only keeps `USERNAME_CHARS` (ASCII letters and digits), using the same filter-on-`text_changed` pattern as `TaxForm._on_answer_changed()`. `_set_busy()` disables all three buttons while a request runs ("Log ind" also stays disabled while `Global.is_logged_in()`). Login (button or Enter in the password field) selects `id, user_name` where `user_name` and `user_login` match. On success it sets `Global.current_user`, shows a green "Login lykkedes" for 1 second and returns to the title screen. Register needs a non-empty username and a password of at least `MIN_PASSWORD_LENGTH` (4) characters, then inserts the row. It does **not** log the player in: on success it shows a green `REGISTER_SUCCESS_TEXT` for 1 second (cleared by a timer signal, not `await`, so leaving the scene is safe). On failure it shows a red "Kunne ikke oprette bruger: …" (empty field, short password, name taken (`23505`), DB error or no connection). `!DEBUG/DebugScenes/test_register/` tests registration against the real database and deletes its `testbot<time>` user afterwards. The title screen's `%LoginStatusLabel` (top-left) shows "Logget ind som <user_name>" / "Ikke logget ind".
- **Dialogue** (`Classes/UIClasses/dialogue.gd`): base `CanvasLayer` for both dialogue autoloads. `start(speaker, lines)` shows the lines, and `ui_accept` or a left click moves to the next one (the event is consumed while visible). After the last line it hides and emits `closed`. With `close_on_any_input` (set on `DialogueText`), any key or click closes it instead, without consuming the event. Each scene needs a unique-name `%TextLabel`. Subclasses override `_refresh()` to update extra UI (`dialogue_box.gd` sets `%NameLabel`).
- **Classes are built in code.** Their `_init` takes arguments (`Board.new(sprite_path, scale)`, `Customer.new("George")`, `Letter.new(txt_path)`), so create them with `.new(...)` + `add_child`, not by instancing a `.tscn`. Exceptions: the rulebook (`rulebook.tscn`) and the calculator (`Addons/Calculator/Resources/scenes/calculator.tscn`) are Boards that are instanced from their scene. Their `_init()` takes no arguments and passes fixed paths to `super(...)`.
- **Customer** (`Classes/CustomerClasses/`): `Customer.new(name, sprite_path = "")` loads by convention from `res://Resources/Customers/<Name>/<name>_data.txt` and `<name>.png` (folder capitalised, file names lowercase). The sprite is scaled by `Global.PIXEL_SCALE`. `Customer.get_random_customer_name()` picks a random folder in `Resources/Customers/` (folders starting with `!` are skipped), so adding a folder adds a customer. Shared customer assets are in `Resources/Customers/!CustomerResources/`. The data file is split into `[SECTION]` headers (`[DIALOGUE]`, `[GREETINGS]`, …). `CustomerData` strips blank lines and gives `read_section(key)` / `read_line(key, n)`; the rulebook pages reuse it. `want_to_speak()` shows a speech-bubble icon and calls `greet()`, which sends a random `[GREETINGS]` line to `DialogueText`. Clicking the customer (once `can_interact`) calls `speak()` → `DialogueBox`, and `finished_speaking` fires when the dialogue closes. Customers are in the `"customers"` group: `Board._drop()` calls `board_dropped(board, point)`, which emits `board_received(form)` when a `TaxForm` with a non-empty answer is dropped on the customer.
- **Game loop** (`Scenes&Scripts/work_place/work_place.gd`): `work_place.tscn` holds the background, the desk, the bell, the frame (walls), the money/sprint/quota labels and the game-over screen. Setup places the rulebook, the welcome letter, the note paper and the calculator on the desk. The bell (`Scenes&Scripts/GameObjects/bell/bell.gd`) plays a sound, wobbles and calls `get_parent().customer_arrive()` unless `is_serving`, so it must be a direct child of the work place. Then:
  1. `customer_arrive()` tweens in a random customer, who greets.
  2. After the customer's dialogue, a random form from `paper_types` (a `Weighted_Array`: `A_Indkomst` 2, `Aktieindkomst` 1, `Ejendomsværdiskat` 1) is placed on the desk.
  3. The player drags the filled-in form onto the customer → `get_payout()`. Exact within `EXACT_TOLERANCE` pays `MAXPAYMENT * 1.25`. If the correct total is 0 (an `Aktieindkomst` with a net loss), any other answer pays `-MAXPAYMENT`; this check must stay ahead of the Gauss formula, which divides by the correct total. Otherwise the pay follows a Gauss curve on the error, from `MAXPAYMENT` down to `-MAXPAYMENT`. Then the customer leaves.
  4. **Sprints**: after `sprint_size` customers, `sprint_money` must reach `sprint_quota`. If it does, `complete_quota()` runs: `save_money()` adds the surplus (`sprint_money - sprint_quota`) to `Global.savings` and resets `sprint_money` and its label (the big label only shows the current sprint), `quotas_served` goes up by 1, and the next sprint is one customer longer with a higher quota. If not, `game_over()` sets `Global.game_over`, resets `quotas_served` and `Global.savings` to 0, fades the music and drops the game-over screen, whose retry button reloads the scene.
  5. **Saving progress** (logged-in players only): `_ready()` calls `load_user_progess()`, which reads the `Progress` row and calls `_setup_sprint(quotas_served)`. That function derives everything else: `sprint_size = first_sprint_size + completed`, and the quota is `get_sprint_quota(sprint_size)`, which gives `FIRST_SPRINT_QUOTA` for 0 completed. `start_new_sprint()` uses it too. While loading, `customer_arrive()` does nothing. If loading fails, `has_loaded_progress` stays false and nothing is saved that game, so a fresh sprint 1 can't overwrite the real progress. `save_user_progess()` upserts `quotas_served` and `Global.savings` and is only called when a sprint ends (from `complete_quota()` and `game_over()`, which set the values first). The retry button stays disabled until the reset is saved (`is_saving` / `progress_saved`). Progress within an unfinished sprint isn't saved. `!DEBUG/DebugScenes/test_progress/` tests all of this against the real database (it uses 1 of the 30 registrations an hour and deletes its user afterwards).

  The `Test` input action (the `å` key) is a debug shortcut: it forces `complete_quota()` and prints the current form's correct answer. When logged in, that also saves progress, possibly with a negative surplus. `_input()` ignores all keys while a `TextEdit` (the note paper) has focus, so players can type "å" in their notes.
- **Desk** (`Scenes&Scripts/GameObjects/desk/desk.gd`): an `Area2D` in the `"desks"` group. `place_board(board, offset)` adds the board as a sibling of the desk (same parent as the other boards, so stacking works), centred at `offset` from the desk's centre. A board with an icon starts in icon mode. `spawn_board(texture_path, offset, …)` builds a plain `Board` and places it. `board_dropped(board)` (from `Board._drop()`) updates `board.on_desk` and emits `board_placed`.
- **Board** (`Classes/ObjectClasses/Board.gd`): a draggable paper sprite in the `"boards"` group.
  - **Constructor**: `Board.new(sprite_path, sprite_scale := 1.0, icon_path := "", icon_scale := 0.25)`. `sprite_scale` is multiplied into the sprite. `size` comes from the texture, and `centered = false`.
  - **Icon mode**: a board with an icon shows as a small icon while it's over a desk and as the full paper elsewhere (`set_icon_mode()`). It switches while dragging, and as an icon only the icon is shown.
  - **Input**: `_input`, ignored while `Global.game_over`. A press on the topmost board under the mouse calls `bring_to_front()` right away and arms a drag. The press is not consumed, so Controls on the paper (the answer `LineEdit`, buttons) still get normal clicks (`_input` runs before GUI picking). The drag starts after the mouse moves `DRAG_THRESHOLD` (6 px). It then releases GUI focus (`_cancel_gui_press()`) and consumes motion events while dragging. Draw order is the child index (`bring_to_front` uses `move_child`). `_drop()` notifies every desk and customer. `_is_over_control()`, `_is_covered_at()` and `_event_position()` are currently unused.
  - **Clipping (disabled)**: boards no longer stick together. The two call sites that created clips are commented out: `clip(get_board_under())` in `_drop()` and `lift()` at drag start. `clip`/`unclip`/`lift`/`get_group` and `clipped` (a two-way adjacency list) are kept so it can be re-enabled and because `test_rulebook` calls them. With no clips, `get_group()` returns `[self]`.
  - **Helpers**: `set_enabled(bool)` hides a board and removes it from input, clips and the group. `replace_with(other)` swaps a board for another in the same place, layer and clips; the rulebook uses it to turn pages. `_make_label(text, font_size)` builds a black, `MOUSE_FILTER_IGNORE`, word-wrapped label, and the constants `FONT_SIZE` / `TITLE_FONT_SIZE` live here too.
  - **Gotcha**: `_ready()` hides child index 2 when a board has exactly 3 children (meant for a form's VBox: sprite, icon, box). `calculator.gd` and `NotePaper` re-show their control because of this.
- **TaxForm** (`Classes/ObjectClasses/TaxForm.gd`): an `@abstract` subclass of `Board` with no constructor, so `TaxForm.new()` is an error. The concrete forms are `A_Indkomst` (monthly or yearly via `periods`), `Aktieindkomst` and `Ejendomsværdiskat`.
  - **A concrete form's `_init()`** must call `super("<paper sprite path>", <scale>, <icon path>, <icon scale>)`. This is required, because `Board._init` needs a sprite path. It then calls `_build_ui()`.
  - **Abstract hooks** it implements: `get_form_title()`, `get_correct_total() -> float` and `_add_fields(box: VBoxContainer)` (the form's own info lines).
  - **What `TaxForm` provides** (Template Method): `_build_ui()` (title → `_add_fields` → `answer_field` LineEdit), `validate() -> float` (correct total minus the parsed answer, overridable for multi-field forms), the static helpers `_kr()` (Danish amount formatting), `_parse_kr()` and `_progressive_tax(grundlag, periods)` (mellem-, top- and toptopskat from `PROGRESSIVE_BRACKETS`, 2026 limits), and `AM_RATE`. `FONT_SIZE`, `TITLE_FONT_SIZE` and `_make_label()` are inherited from `Board`.
  - **Answer field**: it only accepts digits, `,` and `.` (`ANSWER_CHARS`). `_on_answer_changed()` strips everything else on `text_changed`, for both typing and paste.
  - **Adding a form**: write the class, add it to `setup_paper_types()` in `work_place.gd`, and add a rulebook page (below).
- **Rulebook** (`Scenes&Scripts/InteractiveScenes/rulebook.gd` + `.tscn`): a Board with one button per page in `PAGES` (txt files in `Resources/Rulebook/Pages/`). A button swaps the book for that `RulebookPage` with `replace_with()`, and the page's "Tilbage" button (`closed` signal) swaps back. Pages aren't children of the book, which frees them itself.
- **RulebookPage** (`Classes/ObjectClasses/RulebookPage.gd`): a Board built from a txt file with `[TITLE]`, `[LEFT]` and `[RIGHT]` sections (one label per line, two columns).
- **Letter** (`Classes/ObjectClasses/Letter.gd`): extends `RulebookPage`. It's an envelope icon on the desk and a portrait page with one column and no "Tilbage" button. `Letter.new("res://Resources/Letters/welcome_letter.txt")` is placed at game start; write the whole text under `[LEFT]`.
- **NotePaper** (`Classes/ObjectClasses/NotePaper.gd`): a scratch paper for the player's results and calculations. `NotePaper.new()` takes no arguments (paper `rulebook_page_placeholder.png` × 0.6 = 360×240, icon `noteBoard.png` × 0.07). The whole paper is one `TextEdit` (`text_edit`: transparent background, black text, word wrap). The text stays while the paper is an icon but is not saved when the game closes. A click on the note while another board lies on top of that spot is swallowed in `_on_text_gui_input()` (form labels ignore the mouse, so the click would fall through otherwise). One note is placed at game start.
- **Weighted_Array** (`Classes/DatatypeClasses/`): `add(value, weight)` and `pick_weighted_random()`.
